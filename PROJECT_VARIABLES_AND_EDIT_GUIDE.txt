1. HOW TO EDIT BOT REPLY TEXTS & KEYBOARDS (`POOLS` IN `offline_spec_01..05.py`)
================================================================================
Every bot reply in the entire AI lives inside the `POOLS` dictionary of the 5
spec files (`offline_spec_01_core.py` through `offline_spec_05_step17_english.py`).
After editing any text in `POOLS`, simply run:
   python offline_train.py
It will re-pack `http_blob_u8` into `model_weights.npz` automatically!

A. EXACT FORMAT OF A `POOLS` ENTRY:
--------------------------------------------------------------------------------
    "pool_key": (
        class_id,          # int (0..54 or 99) -> JSON "class_id"
        "false",           # str ("true" only for Class 1 & 6, else "false") -> JSON "is_greeting"
        "intent_name",     # str -> JSON "intent"
        (                  # tuple of reply strings -> JSON "reply"
            "reply variation 1",
            "reply variation 2",
            "reply variation 3",
            "reply variation 4",
            "reply variation 5",
            "reply variation 6",
            "reply variation 7",
            "reply variation 8",
        ),
        '["btn 1","btn 2","btn 3"]',  # valid JSON array string -> JSON "kbd"
    ),

B. 3 GOLDEN RULES WHEN EDITING REPLY TEXTS (NEVER VIOLATE!):
--------------------------------------------------------------------------------
1. POWER-OF-2 TUPLE LENGTH (1, 8, 16, or 32 strings per pool):
   - `production_server.py` uses bitwise AND (`rot & pool_mask`) where
     `pool_mask = len(msgs) - 1` for O(1) zero-division rotation.
   - Therefore, every reply tuple MUST contain exactly **8 strings**
     (or **32 strings** for `"greet_first"`, or **1 string** for `"reject"`,
     `"underage"`, `"reset"`). NEVER put 7, 9, or 10 strings in a pool!
2. STEP 9 PERSONA-LOCKED NAME POOLS (`plock=1` on Leaves 27 & 28):
   - In `"name_ask_f"`, `"name_ask_f_rep"`, `"name_tell_f"`, `"name_tell_f_cmp"`:
     * EVEN indices (0, 2, 4, 6) MUST use the name **"Emma"**.
     * ODD indices  (1, 3, 5, 7) MUST use the name **"Sarah"**.
   - In `"name_ask_m"`, `"name_ask_m_rep"`, `"name_tell_m"`, `"name_tell_m_cmp"`:
     * EVEN indices (0, 2, 4, 6) MUST use the name **"Alex"**.
     * ODD indices  (1, 3, 5, 7) MUST use the name **"Liam"**.
   - Why? `production_server.py` indexes `plock=1` pools via
     `idx = ((uid & 1) | ((rot & 3) << 1))` so each user's bot keeps the
     exact same name across the entire session!
3. STEP 14 BOT-CHECK POOLS (`"bot_no"`, `"bot_no_cmp"`, `"bot_real"`, `"bot_real_cmp"`, `"bot_rep"`):
   - NEVER start a reply with `"yes"`! Always say `"haha no im not a bot! im 100% real :)"`
     or `"im 100% real, not a bot haha! :)"`.

2. ALL INTERNAL VARIABLES OF `offline_spec_0X_*.py` & HOW TO EDIT THEM
================================================================================
Every `offline_spec_0X_*.py` file exports up to 8 top-level objects auto-discovered
by `offline_fsm_compiler.py`:

1. `POOLS` (dict):
   - Maps `pool_key_str -> (class_id, is_g_str, intent_str, replies_tuple_len_8, kbd_json_str)`.
2. `LEAF_BINDINGS` (tuple of 4-tuples):
   - Format: `(leaf_id, class_id, "p_norm", {optional_kwargs_dict})`
   - Supported keys inside `optional_kwargs_dict`:
     * `"p_cmp"`:    Pool key when user profile is complete (`age >= 18 and country > 0`).
     * `"p_part"`:   Pool key when user profile is partial (`age >= 18` only).
     * `"p_rep"`:    Pool key when user repeats this intent (`(flags_lo & chk) != 0` or same age/country).
     * `"p_chg"`:    Pool key when user changes their age or country (`RULE_AGE` / `RULE_COUNTRY`).
     * `"p_m"`:      Pool key for Male Bot (`bot_gender == 1`, normal state).
     * `"p_m_cmp"`:  Pool key for Male Bot (complete profile state).
     * `"p_m_rep"`:  Pool key for Male Bot (repeat state).
     * `"p_m_part"`: Pool key for Male Bot (partial profile state).
     * `"chk"`:      `np.uint32` bitmask in `flags_lo` to check for repeat (`F_ASKED_AGE`, `F_BOT_NAMED`, etc.).
     * `"set_f"`:    `np.uint32` bitmask in `flags_lo` to set after this leaf triggers (default `F_GREETED`).
     * `"rule"`:     Entity rule code (`RULE_STD=0`, `RULE_AGE=1`, `RULE_COUNTRY=2`, `RULE_SET_G_F=3`, `RULE_SET_G_M=4`, `RULE_GREET=5`).
     * `"plock"`:    `1` to lock bit 0 of pool index to `uid & 1` (used for Step 9 Emma/Sarah & Alex/Liam).
3. `LEAF_STEP_BITS` (dict):
   - Maps `leaf_id -> int (1..29)`. Sets which bit in `super_bloom_u32` is activated by words in this leaf.
4. `ASKBACK_REDIRECTS` (tuple of 2-tuples):
   - Format: `((prev_leaf_id, target_leaf_id), ...)`
   - Compiles into `askback_redirect_u8[prev_leaf_id] = target_leaf_id`. When user sends `"u"` / `"u?"` / `"wbu?"` (`Leaf 76`) on the next turn, it redirects to `target_leaf_id`.
5. `CORE_LEAF_SEEDS` (dict):
   - Maps `leaf_id -> ("phrase 1", "phrase 2", ...)`.
   - Trained at high weight (`28.0` for positive leaves, `45.0` for `Leaf 0, 76, 77`) so core phrases always override noisy external `.txt` lines.
   - **To add a new English phrase to an existing intent:** Simply add the lowercase string to `CORE_LEAF_SEEDS[leaf_id]`!
6. `ZERO_FAULT_SUITE` (tuple of 3-tuples):
   - Format: `((b"raw user message", expected_class_id, expected_leaf_id), ...)`
   - Verified in Pure NumPy INT8 before `offline_train.py` exports `model_weights.npz`.
7. `MULTI_TURN_SUITE` (tuple of 2-tuples, optional):
   - Format: `(((b"turn1_msg", b"turn2_msg"), (expected_leaf1, expected_leaf2)), ...)`
8. `load_txt_samples(sample_map, load_fn)` (function, optional):
   - Calls `load_fn("filename.txt", cap)` and inserts `(leaf_id, np.float32(weight))` into `sample_map`.
